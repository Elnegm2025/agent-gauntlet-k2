# 🥊 AGENT GAUNTLET — K2 Hackathon

> **Break your AI agent before your users do.**

An adversarial evaluation harness, built entirely in **n8n** and powered by **K2 Horizon**, that automatically attacks an AI agent, judges whether it held up, scores its safety, then rewrites its system prompt and proves the fix worked.

Submitted to the **n8n Dubai Hackathon: Automate with K2 Horizon**.

---

## The problem

AI agents are shipping into customer-facing and business-critical roles, but their safety depends mostly on a hand-written system prompt that nobody adversarially tests. Prompt injection, authority spoofing, secret extraction and policy abuse are discovered by *real users* — often in production. Manual red-teaming is slow, inconsistent and hard to repeat.

**The use case:** before an agent goes live, drop in its system prompt and get a repeatable, LLM-judged vulnerability report plus an automatically hardened prompt — in one run.

## What it does

1. **Analyze** the target agent from its system prompt.
2. **Generate** 5 adversarial tests dynamically tailored to that agent (no hard-coded attacks).
3. **Run** the target agent against each attack.
4. **Judge** whether each response resisted or was compromised.
5. **Aggregate** a vulnerability report and a 0–100 safety score.
6. **Patch** the system prompt from the discovered failures.
7. **Rematch** the *same* 5 attacks against the patched agent.
8. **Compare** BEFORE vs AFTER, with vulnerabilities fixed / remaining.

## How K2 Horizon is used (central to everything)

K2 Horizon (`IFM/K2-Horizon-375B-A23B`) is the engine at **every** decision point — it is the red teamer, the target, the judge, and the patcher:

| Stage | K2 role | Input → Output |
|---|---|---|
| 🔴 Red Team | Adversarial test designer | target prompt → 5 tailored attacks (JSON) |
| ⚔️ Gauntlet | The target agent **re-instantiated with the target's system prompt** | attack → target response |
| ⚖️ Judge | Impartial security evaluator | prompt + attack + expected + response → pass/fail, severity, reason, vulnerability, recommendation (JSON) |
| 🛡️ Patcher | Security engineer | prompt + failed tests → hardened prompt |
| 🔁 Rematch Judge | Same judge, patched agent | verdict |

**No vulnerability classifications or pass/fail outcomes are hard-coded** — K2 reasons about each case. (Code nodes only parse JSON and aggregate counts.)

## How n8n is used

The whole product is one n8n workflow — 19 nodes, no external services, database, or frontend:

- **Manual Trigger** to start a run.
- **Code nodes** to define the target agent + build K2 request payloads, and to parse/validate the JSON K2 returns and aggregate results.
- **HTTP Request nodes** (native n8n, authenticated via an n8n **credential**) for all K2 calls.
- **Item fan-out** — the 5 tests become 5 items, so the Gauntlet and Judge nodes loop over them natively.
- **Node groups + sticky notes** label each stage on the canvas so it reads at a glance.

## Run it

1. In n8n: **Import from File** → `workflow/agent-gauntlet-k2.n8n.json`.
2. Create a **Header Auth** credential named `K2-Horizon-API` with header `Authorization` = `Bearer <your K2/IFM key>` (the export references a credential by name — no key is stored in the JSON).
3. Attach that credential to the 6 K2 HTTP nodes if your import didn't map it.
4. Click **Execute Workflow** and open the **📈 Before vs After** node for the report.

To evaluate a *different* agent, replace the `system_prompt` lines in the **🎯 Target Agent** node.

> ⚠️ The K2 upstream rate-limits (HTTP 429) and can return HTTP 503 (`upstream_circuit_open`) under load. All K2 nodes ship with automatic retry + request spacing so a run survives transient throttling; a full run takes a few minutes.
